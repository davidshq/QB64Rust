# Divergence register

Every intentional difference between QB64Rust and the observed behaviour of the old compiler (QB64pe 4.7.0,
`16f629784e`, Windows). A row is added only when a difference has been **decided**; open choices stay in
`study\00` §6 until then (all of them were decided on 2026-10-08). The numeric rules themselves are the spec
`openspec\specs\language\numeric-semantics`. A row whose "Pinned by" says "not yet" is decided but not implemented:
until it is, the new compiler marks the case "not supported yet" or behaves as the old one, as the row says.

"Default" is the old compiler's normal build; "`-O2`" is its build with "optimize C++" on
(`-f:OptimizeCppProgram=true`). Where they behave the same only one value is given.

| Id | Behaviour | Old compiler | QB64Rust | Reason | Decided | Pinned by |
|---|---|---|---|---|---|---|
| D-001 | LONG (and INTEGER, computed in 32 bits) overflow in `+ - *` | Default: wraps (`2147483647 + 1` = `-2147483648`, `x + 1 > x` false). `-O2`: undefined behaviour in the generated C++; `x + 1 > x` is **true** and `PRINT x + 1` prints ` 2147483648 ` (`verification\v11_wrap_o2.out.txt`, `.O2.out.txt`) | Always wraps in two's complement, in generated code (`-fwrapv`) and in constant folding | Equals the default build; makes `-O2` irrelevant to results | 2026-10-03, panel (`study\16` §8) | `tests\corpus\verification\v11_wrap_o2`, `tests\corpus\slice\s02_integer_wrap` |
| D-002 | `_INTEGER64` overflow in `+ - *` | Default: wraps (`x + 1 > x` false). `-O2`: `x + 1 > x` is **true**; the printed value still wraps (`verification\v12_wrap_int64.out.txt`, `.O2.out.txt`) | Always wraps, like D-001 | Same exposure as LONG; same reason | 2026-10-03, user (`DECISIONS.md`, `study\16` §8) | `tests\corpus\verification\v12_wrap_int64`, `tests\corpus\slice\s02_integer_wrap` |
| D-003 | `RETURN label` with no `GOSUB` pending | Raises error 3, then decrements the `GOSUB` counter anyway (`qb64pe.bas` 9948), so it wraps below zero and the next `GOSUB` crashes the program (exit code 139; `verification\v17_d_return_label_none.out.txt`) | Raises error 3 and leaves the counter at 0; a later `GOSUB` and `RETURN` work | The old result is memory corruption, not behaviour a program can rely on | 2026-10-06, user (`m2-control-flow-slice` design D8) | `cpp` snapshot `tests\frontend\emit_gosub_cpp.bas`; CLI test `return_label_with_nothing_pending` (builds and runs; `#[ignore]`d, needs the clone) |
| D-004 | A store into a member of an array element whose index is out of range (`a(9).m = 5` for `DIM a(3) AS t`), with the program going on (`RESUME NEXT`, or `QB64PE_NOPROMPT=continue`) | Raises error 9 and **writes the value into element 0** (`a(0).m` becomes 5; also for `STRING` members): `array_check` returns 0 after raising and member stores are not guarded (`verification\v18_b_member_store.out.txt`) | Raises error 9 and stores nothing. The value is still evaluated before the index and the first error still wins, as measured (`a(9).m = ASC("")` reports 5). The same when an index raises with no error pending before it (`a(ASC("")).m = 6`: the old compiler writes `a(0).m`, `verification\v18_b_index_raises`), as an element store does. An index that raises while the value's error is pending cannot be told apart (the first error wins) and stores as the old compiler does | Writing an element the program did not name is wrong code; an element store `x(9) = 5` already writes nothing | 2026-10-07, user (`m2-arrays-and-types` design D6) | `cpp` and `ir` snapshots and a slice program (task 6.2 of `m2-arrays-and-types`) |
| D-005 | `a IMP b IMP c` (an `IMP` whose left operand is an `IMP`) | Computes `a OR b OR c`: the left `IMP`'s C text loses its parentheses (`~~5\|3\|0`), so `5 IMP 3 IMP 0` gives 7 (`verification\v17_g_imp_eqv`, `study\00` §5) | Computes `(a IMP b) IMP c`, as the definition and every other `IMP`/`EQV` combination measured (`5 IMP 3 IMP 0` gives 4: `5 IMP 3` is -5, `-5 IMP 0` is 4) | A code-generation slip, not behaviour | 2026-10-08, user (`study\00` §6) | Not yet: "not supported yet" today (`m2-control-flow-slice`) |
| D-006 | The smallest LONG or `_INTEGER64` with `\ -1` or `MOD -1` | The program crashes (exit code 127, no output, even with an `ON ERROR` handler; `verification\v17_g_long_min_div`, `v17_g_int64_min_div`) | `\ -1` raises error 6 (Overflow, trappable, as QB 4.5); `MOD -1` gives 0, its exact result | A crash is not behaviour | 2026-10-08, user (`study\00` §6) | Not yet: crashes as the old one today (`qb_safe_idiv`, `qb_safe_mod`); the numeric-semantics spec leaves it unspecified |
| D-007 | `CONST` values the old evaluator gets wrong: `CONST c = 1 / 0`; an integer power beyond `_INTEGER64` (`CONST c = 2 ^ 70`) | `1 / 0` gives 0; `2 ^ 70` wraps to -9223372036854775808, while `1E+19 / 1` stays the DOUBLE `1D+19` (`verification\v17_e_const_fdiv0`, `v17_e_const_big_float`) | `1 / 0` is a compile error ("Division by zero"); `2 ^ 70` is a DOUBLE, by the old evaluator's own rule for floats outside `_INTEGER64` range | Both are wrong values silently built into the program | 2026-10-08, user (`study\00` §6) | Not yet: "not supported yet" today |
| D-008 | A label and `CONST` on one line (`lbl1: CONST k = 4`) | Compile error ("NULL string; nothing to evaluate", or "Unexpected element '='", depending on the label's length; the prepass strips the label wrongly, `verification\v05_label_const`, `v05b_label_const_short`) | Compiles: the label, then the `CONST` | A parser bug; `lbl3: TYPE t` on one line works | 2026-10-08, user (`study\00` §6) | Not yet: "not supported yet" today |
| D-009 | A `_BIT * n` scalar with n > 32 | Its 8-byte C type gets 4 bytes, so a store overwrites 4 bytes of the `_BIT` scalar (of any width) allocated just before it; other variables are not hit (`verification\v04_accidental`, `v21_b_bit_overlap`) | Each variable has its own storage | Memory corruption | 2026-10-08, user (`study\00` §6) | `cpp` snapshot `tests\frontend\bit_stores_cpp.bas` (8 bytes for n > 32); CLI test `wide_bit_scalars_do_not_overlap` (builds and runs; `#[ignore]`d, needs the clone) |
| D-010 | Printing an infinite SINGLE or DOUBLE (`PRINT 1 / z!`) | ` INF           ` (SINGLE) and ` INF              D     ` (DOUBLE): padding and a stray exponent letter (`verification\v02_errors`) | Printed without the padding and the stray `D`; the exact text is set when it is implemented, from what `STR$` gives | A formatting defect | 2026-10-08, user (`study\00` §6) | Not yet |
| D-011 | A comma in `PRINT` to the console (`$CONSOLE`) | Windows: pads with spaces until the console window's cursor column is a multiple of 10, asked through a new `CONOUT$` handle each time (never closed); with stdout redirected the cursor never moves and the program writes spaces forever (`study\10` §2.2). Linux and macOS: one space (read, not run) | Same zones (10 on Windows, one space elsewhere: user, "do exactly as QB64pe"), but the runtime counts the console column itself: no hang when redirected, no handle leak. Output may differ only where something other than the program moved the console cursor | The hang and the leak are defects; the zones are kept | 2026-10-08, user (`study\00` §6; 14 everywhere to evaluate, `SOMEDAY.md`) | Not yet: console comma output is the runtime's |
| D-012 | Exit code after an unhandled runtime error (with `QB64PE_NOPROMPT=y`, or "continue? no") | 0 (`verification\v02c_no_handler`) | Non-zero; the value is set when it is implemented | Scripts and test runners must be able to see the failure | 2026-10-08, user (`study\00` §6) | Not yet |
| D-013 | `_LOGMINLEVEL` and `_SCREENEXISTS` | Registered without a return type (`study\10` §3: `_LogMinLevel` sets `ideret` instead of `id.ret`, `_ScreenExists` has no `id.ret` line) | Functions with the return type their wiki pages give | A registration slip | 2026-10-08, user (`study\00` §6) | Not yet |

D-001 and D-002 differ from the old compiler only in its `-O2` build; the corpus is recorded with the default build,
so these programs pass unchanged. D-003 differs only after a program would have crashed. D-004 differs only after an
error 9 the program chose to ignore. D-005 to D-013 change what a program the old compiler builds does only where it
crashes, hangs, corrupts memory or computes a value by a slip (D-005, D-007); D-008 and D-013 accept programs the
old compiler rejects.
