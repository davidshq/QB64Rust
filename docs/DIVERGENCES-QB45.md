# Divergences from QuickBASIC 4.5

Where QB64Rust behaves differently from QuickBASIC 4.5. The companion of `QB64PE-DIVERGENCES.md`, which registers the
differences from the old compiler (QB64pe); QB64Rust follows QB64pe where the two differ unless a row there says
otherwise, so most rows here are differences QB64Rust inherits from QB64pe. A row is added when a behaviour is
decided and QB 4.5 is known or believed to differ (decided 2026-10-07, user).

QB 4.5 runs on the development machine under DOSBox since 2026-10-26 (`tools\qb45\README.md`; QB 4.5 itself is
outside the repo). Each row says where its QB 4.5 behaviour comes from: **documented** (Microsoft's QB 4.5 manuals
or help), **believed** (from memory of how QB 4.5 works, not checked), or **measured** (built with QB 4.5's `BC` and
run under DOSBox, with the program in `verification\qb45\`). Rows that are not measured can now be checked with
`tools\qb45\qb45.py`.

| Id | Behaviour | QuickBASIC 4.5 | QB64Rust (= QB64pe unless noted) | Source of the QB 4.5 column | Decided | Pinned by |
|---|---|---|---|---|---|---|
| Q-001 | `ON n GOTO` / `ON n GOSUB` with `n` above 255 | Error 5, "Illegal function call" (`n` must be 0 to 255) | Continues with the next statement, as for `n` = 0 or `n` beyond the number of labels; a negative `n` raises error 5 in both | Documented | 2026-10-07, user (`m2-core-builtins`) | `tests\corpus\slice\s29_on_goto` (`ON 258 GOTO`, 255, 256 in a loop; measured `verification\v20_i_on_goto`) |
| Q-002 | `SELECT CASE` in a recursive procedure: the copy of the test expression | Kept in the procedure's stack frame, so each call has its own and a recursive call between the test and a later `CASE` does not change it | One static copy per `SELECT` statement (QB64pe since its first version, `qb64pe.bas` "static … sc_"), so a recursive call overwrites it and the outer `SELECT` tests the inner call's value at its later `CASE`s (`verification\v04_accidental`) | **Believed; to measure with QB 4.5 under DOSBox** | 2026-10-07, user (`m2-core-builtins`: keep QB64pe's behaviour) | `tests\corpus\slice\s28_select_case` (`rec(1) = 2`; measured `verification\v20_h_select`) |
| Q-003 | Division by zero with an `ON ERROR` handler: integer `\` and `MOD` by 0, `ERROR 11`, a float `/` by 0 | Error 11, "Division by zero", trapped by the handler, for all four | Integer `\`, `MOD` and `ERROR 11`: error 11, trapped, as QB 4.5 (`QB64PE-DIVERGENCES.md` D-052, OpenSpec change `libqb-fixes`; `verification\v63_e1`, `e2`). Still different: a float `/` by 0 gives infinity, with no error (a candidate for the fixes switch, `study\39` §4) | Measured (`verification\qb45\q45_div_zero`: `\`, `MOD`, `ERROR 11` and a float `/` by zero each trapped as 11) | 2026-10-08, user (`study\00` §6: keep QB64pe's); 2026-10-26, user: the integer forms fixed always, trappable as in QB 4.5 (row 12 of the crash-class rulings, `study\39`), built 2026-10-27 | `verification\v63_e1`, `e2` (the new compiler's output differs from QB64pe's recording, `tests\verification\known.list`) |
| Q-004 | INTEGER arithmetic beyond the INTEGER range inside an expression (`i% = 32767: PRINT i% + 1`) | Error 6, "Overflow" | Computed in 32 bits: prints 32768; only the store into an INTEGER wraps (`i% = i% + 1` gives -32768). LONG wraps too (`QB64PE-DIVERGENCES.md` D-001) | Believed | 2026-10-08, user (`study\00` §6: keep QB64pe's) | `tests\corpus\slice\s02_integer_wrap` |
| Q-005 | The initial bytes of a fixed-length string (`DIM f AS STRING * 4`, also in a `TYPE`) | Spaces | NUL bytes (0); assignment still pads with spaces (`verification\v03_storage`) | Believed | 2026-10-08, user (`study\00` §6: keep QB64pe's) | `tests\corpus\slice\s33_fixed_strings` (variables, a local on each call, `STATIC`, members, elements); `cpp` snapshot `tests\frontend\fixed_strings_cpp.bas` |
| Q-006 | `PRINT` with a comma when the program writes to the console (`$CONSOLE`), e.g. a QB 4.5 screen program built as `$CONSOLE:ONLY` | 14-column zones on the screen (QB 4.5 has no console) | Windows console: 10-column zones; Linux and macOS console: one space (read, not run); window and files: 14-column zones (`study\00` §6, `QB64PE-DIVERGENCES.md` D-011) | Documented | 2026-10-08, user (`study\00` §6: exactly as QB64pe; 14 everywhere to evaluate, `SOMEDAY.md`) | Not yet: console comma output is the runtime's |
| Q-007 | `STRING$(n, "")` | Error 5, "Illegal function call" | Reads the first byte of the empty string (`verification\v20_c_string_edges`) | Believed | 2026-10-08, user (`study\00` §6: keep QB64pe's) | Measured on the old compiler only (`verification\v20_c_string_edges`); no slice program yet |
| Q-008 | `CONST c = 2 ^ 3 ^ 2` (a chain of `^` in a `CONST`) | Believed left-associative, as at run time: 64 | Right-associative in a `CONST` only: 512 (64 at run time), with a compiler warning (`verification\v17_e_const`) | Believed | 2026-10-08, user (`study\00` §6: keep QB64pe's, add the warning) | `tests\corpus\slice\s18_const` |
| Q-009 | An array used without `DIM` inside a SUB or FUNCTION (`x(2) = 5` with no array `x` declared there) | Believed: a local array 0 to 10 (`OPTION BASE` to 10) per dimension, as in the main module | Every use raises error 9, on every call: QB64pe makes a local dynamic array and writes nothing that allocates it; a `DIM` or `REDIM` of the name later in the procedure does. Only in a `SUB … STATIC` (not below `$DYNAMIC`) is it a working array, 0 to 10, kept between calls (`verification\v24_f_implicit_sub`, `v24_x120`, `x176`) | Believed | 2026-10-11, user (task 1.4 of `m2-defxxx-common-arrays`: do as QB64pe, note the difference) | `tests\corpus\slice\s55_implicit` (a SUB and a FUNCTION), `s56_proc_arrays` lines 18 and 23 (a `DIM` after the use; a `SUB … STATIC`) |
| Q-010 | A `SUB … STATIC` or `FUNCTION … STATIC` that holds a `STATIC` statement: the variables and arrays first named below that statement | Documented: `STATIC` after the header makes every variable of the procedure keep its value between calls | Kept only when first named above the procedure's first `STATIC` statement; below it new variables are made on each call and a `DIM` is a local dynamic array (QB64pe's flag for the procedure is reset at the end of a `STATIC` statement). A procedure without a `STATIC` statement keeps everything | Documented | 2026-10-08, user (the standing rule: as QB64pe; listed for review in `SOMEDAY.md`) | `tests\corpus\slice\s56_proc_arrays` line 21 (`verification\v24_x279`) |
| Q-011 | A `PLAY` string with a tempo or an octave outside QuickBASIC's range (`PLAY "T31 C"`, `"T256 C"`, `"O7 C"`) | Error 5, "Illegal function call": the tempo is 32 to 255 quarter notes a minute, the octave 0 to 6 | Played with no error (libqb takes any tempo and octave it can compute with); a length of 0 or above 64, a note above 84 and an unknown command are error 5 in both | Documented | 2026-10-13 (the standing rule: as QB64pe; listed for review in `SOMEDAY.md`) | `tests\corpus\slice\s76_sound_errors`, its statements 42 to 44 (`verification\v29_c_sound_errors`) |
| Q-012 | `ON PLAY(n) GOSUB`, `PLAY ON`, `PLAY OFF`, `PLAY STOP` (the event of the background music buffer) | An event: the handler runs when fewer than `n` notes are left to play | No such event. `ON PLAY(n) GOSUB label` is `ON <number> GOSUB` with the function `PLAY`; `PLAY ON`, `PLAY OFF` and `PLAY STOP` are compile errors | Documented | 2026-10-13 (as QB64pe) | `tests\frontend\sound_typed.bas`, `sound_errors.bas` (`verification\v29_x61`-`x64`) |
| Q-013 | `LSET` with two variables of a user type (`LSET r = r2`) | Copies the bytes of one record variable into the other, also between two types | A compile error: the target of `LSET` and `RSET` is a string variable, element or member (`r = r2` copies a value of one type) | Documented | 2026-10-13 (as QB64pe) | `tests\frontend\field_lset_errors.bas` (`verification\v30_x142`, `x158`, `x167`) |
| Q-014 | An assignment with `=` (or `INPUT`) to a string named by `FIELD` | The string is no field any more: it moves out of the record buffer | The string gets the value and its length and stays a field: the next `LSET` to any field of the file, or `GET` with no variable, gives it its width and the buffer's bytes again. A second `FIELD` on a file keeps the strings of the first as fields, as there | Documented | 2026-10-13 (as QB64pe) | Lines 6 to 9 of `tests\corpus\slice\s86_field_lset` (`verification\v30_j_field`) |
| Q-015 | The number in `STATIC a(n)` (and the `STATIC` of an array in a SUB beside a shared array of that name and type) | The number of dimensions: `STATIC a(5) AS LONG` is an array of five dimensions, so `a(1)` is "Wrong number of dimensions"; the array is given bounds by a later `DIM`. Such a `STATIC` declares an array of the SUB's own, also beside a shared array of the same name and type | The upper bound: `STATIC a(5)` is `a(0 TO 5)`. Beside a shared array of the same name and type QB64pe allocates the shared one again (`verification\v24_x272`, `v55_d1`); this compiler will make it the SUB's own, always for a static shared array and behind the fixes switch for a dynamic one | Measured (`verification\qb45\q45_static_dims`, `q45_static_local`) | 2026-10-26, user (row 4 of the crash-class rulings, `study\39`) | Not yet: the fix is not built |
