# Proposal

## Why

This is step 5 of the plan for the rest of M4 (user, `DECISIONS.md` 2026-10-22): **`SUB _GL`, a change of its
own**. Since step 4b it is the last construct the new compiler marks "not supported yet" outside the 9 programs
steps 2 and 3 left marked, and the reason `opengl/test` is one of the three upstream programs off the pass list
(`SUB _GL STATIC` calling `_glViewport 0, 0, _WIDTH, _HEIGHT`).

What the old compiler does (read in `..\QB64pe\source`, to be measured by `verification\v59`):

- **`SUB _GL` without parameters is the program's OpenGL routine** (`qb64pe.bas` 3066: the first such SUB sets
  `UseGL` and `DEPENDENCY_GL`). libqb calls it from its render loop, once a frame, at the layer `_GLRENDER` puts it
  (`libqb.cpp`, about 25419–25442), with `sub_gl_called` set while it runs. A program cannot call it ("Cannot call
  SUB _GL directly", `qb64pe.bas` 10863).
- **A program with it gets the OpenGL names**: on each compile the old compiler reads its copy of `gl.h`
  (`internal\c\parts\core\gl_header_for_parsing\gl.h`, also in `libqb\`) and, when `UseGL` is set, registers its
  constants (from 592 `#define` lines) (`_GL_COLOR_BUFFER_BIT` …, each an `_INTEGER64`) and 336 functions and statements (`_glViewport` …,
  every argument `BYVAL`, every pointer an `_OFFSET`), plus `_gluPerspective` (`opengl_methods.bas`,
  `gl_scan_header` and `gl_include_content`). A call goes to the helper `call_glViewport(…)` of
  `gl_helper_code.h`, which libqb's `qbx.cpp` includes under `DEPENDENCY_GL`; the helper raises error 270 when it
  runs outside `SUB _GL`. `END` and `SYSTEM` inside it raise error 271.
- **The build gets `DEP_GL=y`** (`qb64pe.bas` 13706), which compiles libqb with `-DDEPENDENCY_GL` into its own
  object set (`Makefile` 332).

## What Changes

- **A measurement family `verification\v59_*` comes first**: the forms of `SUB _GL` the old compiler accepts and
  rejects (with parameters, as a FUNCTION, twice, called, in a `$CONSOLE:ONLY` program), the OpenGL names with
  and without a `SUB _GL` in the program, their argument conversions, suffixes and the `_INTEGER64` constants,
  `glGetString`'s string, errors 270 and 271, and what a program reads back from OpenGL inside `SUB _GL`. The
  code follows the recordings.
- **`SUB _GL` compiles** as the old compiler's program has it: the routine the render loop calls, `DEP_GL=y` in
  the build, and the old compiler's errors for the forms it rejects.
- **The OpenGL table**: the constants and 337 routines become a table of the new compiler, generated from
  `libqb\`'s `gl.h` by a tool and checked against it and against `gl_helper_code.h` in tier 1. The names exist
  only in a program with `SUB _GL`, as in the old compiler.
- **Each OpenGL routine has a call-site program**, generated by the same tool, so that every call is compared
  with the old compiler's.
- **OpenGL is run, not only compiled**: a program draws in `SUB _GL` and reads the pixels back with
  `_glReadPixels` (and the state with `_glGetIntegerv`), and prints them; its output is compared with the old
  compiler's program. Only values that the driver cannot round differently are compared (a cleared colour, the
  viewport, an error code); a drawn shape is not (working rule 12).
- `opengl/test` joins `tests\upstream\pass.list` (402 of 404); the `cli.rs` test that used `SUB _GL` as its
  example of a construct not compiled yet takes one of the 9 marked programs' forms.

## Capabilities

### New Capabilities

- `language/opengl`: `SUB _GL`, the OpenGL names a program with it may use, how they are called and when, and
  the run-time errors 270 and 271.

### Modified Capabilities

- `testing/compiler-tests`: the coverage of built-ins covers the OpenGL table (a call-site program for each
  routine, a tier 1 check of the table against `libqb\`), and OpenGL joins the parts that a test runs.

## Impact

- `crates\sema`: the OpenGL table (a generated module beside `builtins.rs`), `SUB _GL` in `check\decl.rs`
  (`reserved_proc`) and its calls in `check\proc.rs`, the names looked up only when the program has the SUB.
- `crates\ir`, `crates\codegen-cpp`: `SUB__GL` as the old compiler names it, the calls to `call_gl*`, the setting
  that asks for `DEP_GL`.
- `crates\driver`: `DEP_GL=y` in the make flags (`build.rs`, `make_flags`), so libqb's objects of the GL set are
  built and kept under their own name.
- `tools\opengl\` (new): the generator of the table and of the call-site programs, with `--check` and its own
  tests.
- Tests: `verification\v59_*` and their recordings, the generated call-site programs in `tests\callsite\`, front-end
  tests, `tests\verification\pass.list`, `tests\upstream\pass.list`, `crates\base\src\old_wording.tsv`
  regenerated, `crates\driver\tests\cli.rs`.
